# Agent C++ 代码规范

## 1. 文件头规范

所有 C++ 源文件 (.cpp) 和头文件 (.h/.hpp) 必须使用以下文件头注释模板：

```cpp
/**************************************************************************
* 版权所有(C), 20**，海华电子企业（中国）有限公司
* 文件名：		// 文件名称
* 作  者：		// 作者
* 版  本：		// 软件版本
* 日  期：		// 代码完成日期
* 文件描述:		// 用于详细说明此程序文件完成的主要功能，与其他模块
*				// 或函数的接口，输出值、取值范围、含义及参数间的控
*				// 制、顺序、独立或依赖等关系
* 函数列表： 	// 主要函数列表，每条记录应包括函数名及功能简要说明
* 修改历史:  	// 修改历史记录列表，每条修改记录应包括修改日期、修改
*				// 者及修改内容简述
***************************************************************************/
```

### 1.1 文件头字段说明

| 字段 | 说明 |
|------|------|
| 版权所有 | 年份替换为当前年份，格式：20XX |
| 文件名 | 文件的实际名称 |
| 作者 | 代码编写者姓名 |
| 版本 | 软件版本号，如 v1.0.0 |
| 日期 | 代码完成日期，格式：YYYY/MM/DD |
| 文件描述 | 详细说明文件功能、模块接口、参数关系等 |
| 函数列表 | 列出文件中主要函数及其功能简述 |
| 修改历史 | 记录每次修改的日期、修改者和修改内容 |

### 1.2 修改历史记录格式示例

```
* 修改历史:
* 修改日期：2024/01/15
* 修改者：张三
* 修改内容：初始版本创建
*
* 修改日期：2024/03/20
* 修改者：李四
* 修改内容：添加数据处理功能
```

## 2. 命名规范

### 2.1 文件名
- 头文件使用 `.h` 或 `.hpp` 扩展名
- 源文件使用 `.cpp` 扩展名
- 文件名使用小写字母，单词间用下划线分隔
- 示例：`data_processor.h`, `data_processor.cpp`

### 2.2 类名和结构体
- 使用大驼峰命名法（PascalCase）
- 示例：`DataProcessor`, `UserManager`

### 2.3 函数名
- 使用大驼峰命名法（PascalCase）
- 示例：`ProcessData()`, `GetUserInfo()`

### 2.4 变量名
- 使用小驼峰命名法（camelCase）
- 示例：`userData`, `processCount`

### 2.5 常量名
- 使用全大写字母，单词间用下划线分隔
- 示例：`MAX_BUFFER_SIZE`, `DEFAULT_TIMEOUT`

### 2.6 宏定义
- 使用全大写字母，单词间用下划线分隔
- 示例：`#define MAX_RETRIES 3`

## 3. 注释规范

### 3.1 单行注释
- 使用 `//` 进行单行注释
- 注释与代码之间保留一个空格

### 3.2 多行注释
- 使用 `/* ... */` 进行多行注释
- 避免使用 `/** ... */`（除文件头外）

### 3.3 函数注释
**所有函数必须添加 Doxygen 格式的函数注释。**

```cpp
/**
 * @brief 简要描述函数功能
 * 
 * @param param1 参数1描述
 * @param param2 参数2描述
 * @return 返回值描述
 */
```

## 4. 缩进与格式化

- 使用 4 个空格进行缩进，不使用 Tab
- 大括号风格：K&R 风格（Allman 或 Kremen 均可，团队内需统一）
- 每行代码长度不超过 120 字符
- 花括号"{"或"}"需要单独占一行，不要与函数或者关键字等连着写或者空格后接着写

## 5. 头文件规范

### 5.1 头文件保护
**头文件保护必须使用 `#ifndef`/`#define`/`#endif` 方式，禁止使用 `#pragma once`。**

```cpp
// 文件头注释
// ...

#ifndef SOME_UNIQUE_NAME_H
#define SOME_UNIQUE_NAME_H

// 头文件内容

#endif // SOME_UNIQUE_NAME_H
```

### 5.2 包含顺序
1. 对应头文件
2. C 系统头文件
3. C++ 系统头文件
4. 其他项目头文件

## 6. 编码规范

### 6.1 类型使用
- 使用 `int8_t`, `int16_t`, `int32_t`, `int64_t` 等固定宽度类型
- 使用 `nullptr` 代替 `NULL`
- 使用 `auto` 简化类型声明

### 6.2 内存管理
- 优先使用智能指针 (`std::unique_ptr`, `std::shared_ptr`)
- 避免使用裸 `new`/`delete`

### 6.3 错误处理
- 合理使用异常处理
- 错误信息应清晰明确
- 遵循项目的错误码规范

## 7. Git 提交规范

- 提交信息使用中文
- 格式：`[类型] 简要描述`
- 类型：feat（新功能）、fix（修复）、docs（文档）、refactor（重构）、test（测试）、chore（构建/工具）
